## はじめに

静的サイト向けの全文検索エンジンである [Pagefind](https://pagefind.app/) と Cloudflare Workers + D1 を用いて、Next.js（SSG）の静的サイトに全文検索機能と人気キーワードの集計機能を実装する方法の備忘録。

## 技術構成

| 技術                     | 用途                                              |
| ------------------------ | ------------------------------------------------- |
| **Next.js (App Router)** | フロントエンドフレームワーク                      |
| **OpenNext**             | Next.jsをCloudflare Workersで動作させるために使用 |
| **Cloudflare Workers**   | デプロイ先                                        |
| **Pagefind**             | 静的検索エンジン                                  |
| **Cloudflare D1**        | 検索ログ保存用データベース                        |

## Pagefindによる静的検索の仕組み

Pagefindは、静的サイトのビルド時にインデックスを生成し、クライアントサイドで検索を実行する仕組みです。  
これにより、サーバーサイドの検索エンジンが不要となり、高速な検索体験を提供できます。

- **軽量**: インデックスは分割されており、必要な部分のみがロードされる
- **静的サイトに最適**: 動的なサーバー処理が不要
- **インデックス作成の流れ**
  ```text
  ビルド → HTML解析 → インデックス生成 → クライアントサイド検索
  ```

## 検索ログの保存とモデレーション

検索機能の品質向上のために、ユーザーの検索キーワードをログとして保存し、人気キーワードを集計します。

APIは Next.js の **API Routes** を使用して実装します。

### Cloudflare D1の利用

ユーザーが検索したキーワードは Cloudflare D1 データベースに保存され、人気キーワードの集計に使用されます。

```text
[ユーザー] → [POST /api/search-log] → [モデレーション] → [D1 Database]
              (Next.js API Routes)          ↓
                                   NG: 保存しない
                                   OK: キーワードを保存
```

#### データベーステーブル

| テーブル              | 用途                                 |
| --------------------- | ------------------------------------ |
| `keyword_counts`      | キーワードごとの検索回数を集計       |
| `keyword_search_logs` | セッション別の検索ログ（重複排除用） |
| `rate_limits`         | レート制限の管理                     |

検索回数の水増しを防ぐために、同一セッションからの連続した同じキーワード検索は 1 回としてカウントされるようにします。  
これにより、検索回数の水増しを防ぎます。

### モデレーションの実装

不適切なキーワードの保存を防ぐため、2 層のフィルタリングを実装しています。

```text
検索キーワード
    ↓
[1. leo-profanity（ローカル・高速）]
    ↓ NG → 即座にブロック
    ↓ OK
[2. OpenAI Moderation API（文脈理解）]
    ↓ NG → ブロック
    ↓ OK
データベースに保存
```

#### 第1層: [leo-profanity](https://www.npmjs.com/package/leo-profanity)

**選定理由**: コスト削減とレスポンス速度の最適化

第1層の主な目的は、**明らかに不適切なワードを事前にフィルタリングし、OpenAI APIの呼び出し回数を削減すること**です。

- **ローカル処理**: API 呼び出し不要で高速（レイテンシ < 1ms）
- **コスト削減**: 明らかな不適切ワードは第1層でブロックし、OpenAI API の呼び出しをスキップ
  - 例: 露骨な暴力表現や性的表現など、文脈に関係なく常にNGなワード
- **多言語対応**: `naughty-words` ライブラリで複数言語の禁止ワードをカバー
- **部分一致**: 禁止ワードが含まれていれば検出

#### 第2層: [OpenAI Moderation API](https://platform.openai.com/docs/guides/moderation)

**選定理由**: 文脈を考慮した高精度な判定

第1層を通過したキーワードのみがこの層に到達します。

- **文脈理解**: 単語単位ではなく文脈を考慮した判定
  - 例: "kill" という単語でも、"kill the process"（プロセス停止）と "kill someone"（暴力）を区別
- **カテゴリ別判定**: `sexual`, `harassment`, `hate`, `violence` など複数のカテゴリで評価
- **誤検知の防止**: 技術用語や一般的な単語が誤ってブロックされることを防ぐ
- **フォールバック**: OpenAI API がエラーやダウンした場合は第1層のみで判定し、可用性を確保

OpenAI Moderation API だけのモデレーションでも良かったのですが、2層構造にした理由としては以下の理由があります。

- **高速なレスポンス**: 第1層で処理が完結するケースではAPI通信が不要なため、応答速度が向上
- **誤検知の防止**: 第2層で文脈を考慮した判定を行うため、技術用語などの正当なキーワードが誤ってブロックされるリスクを抑える
- **安定性の確保**: OpenAI APIに障害が発生した場合でも、第1層によるフィルタリングは継続させる

## レート制限の実装

API の悪用を防ぐため、レート制限を実装しています。

- **IP**: 個別IPアドレスからの短時間での大量リクエストを防止
- **セッション**: 同一ユーザーの1日あたりの過度な検索を制限
- **グローバル**: サービス全体への瞬間的な負荷集中を防止

### レート制限の仕組み

レート制限の状態は Cloudflare D1 の `rate_limits` テーブルで管理されます。

```md
// レート制限チェックの流れ

1. リクエスト受信
2. IPアドレスとセッションIDを取得
3. D1から各制限タイプの現在のカウントを取得
4. 制限超過チェック
   - 超過している場合: 429 Too Many Requests を返す
   - 問題ない場合: カウントを増加してリクエストを処理
5. Cloudflare Cron Triggers による古いレコードの自動クリーンアップ（ウィンドウ期間を超過したもの）
```

## 人気キーワードの取得

`GET /api/popular-keywords`（Next.js API Routes）から人気キーワードを取得できます。

### 取得条件

人気キーワードの取得条件は以下の通りです。

| 項目         | 詳細                                 | 理由                                                                   |
| ------------ | ------------------------------------ | ---------------------------------------------------------------------- |
| 最低検索回数 | 5 回以上検索されたキーワードのみ表示 | ノイズとなる偶発的な検索を除外し、実際に需要のあるキーワードのみを表示 |
| 期間         | 直近 7 日以内に検索されたもの        | 最新のトレンドを反映し、古くなった情報を排除                           |
| キャッシュ   | 60 秒間キャッシュされます            | D1への負荷を軽減しつつ、リアルタイム性を維持                           |

### レスポンス例

```json
{
  "keywords": [
    {
      "keyword": "Next.js",
      "count": 42,
      "lastSearchedAt": "2024-01-20T10:30:00Z"
    },
    {
      "keyword": "Cloudflare Workers",
      "count": 28,
      "lastSearchedAt": "2024-01-20T09:15:00Z"
    }
  ]
}
```
